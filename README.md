# 19 · Bit Packing：只保存整数真正需要的位

## 问题与前置知识

数据库列中的小整数若仍按 uint64_t 存放，高位大多为零。位打包把一个块中每个值都用
相同的 w 位连续存放，减少内存和缓存传输。前置知识为二进制、无符号移位、字节数组。
相关主题是 18 游程、20 字典 ID、21 差分；本实现不依赖它们，也不隐式串联其他编码器。

## 位宽与格式

`bit_width(0)=0`；非零值的位宽是最高置位位置加一，等价于 floor(log2(x))+1，
但代码只做整数右移，不使用有舍入风险的浮点 log。
自动编码选择块内最大位宽；显式 `encode(values,width)` 允许更宽表示，
但拒绝 width>64 以及不能容纳的值，不会静默截断高位。

| 字段 | 长度 | 含义 |
| --- | ---: | --- |
| n | 4 字节 | 原始元素数，小端 |
| w | 1 字节 | 位宽 0..64 |
| payload | ceil(n*w/8) 字节 | 每个值低位先写，字节内低位先填 |

全零块只要 5 字节，即使 w=0 也能通过 n 还原个数。空块同样为 5 字节。
尾字节未使用高位必须为零；解码检查精确长度与填充位，拒绝尾随垃圾。
不要求显式宽度必须最小，否则合法的满宽零值块也会被错误拒绝。

## 跨字节轨迹

输入 `[1,7,3,5]`，最大值 7，w=3。
每个值按低位到高位贡献 `100 | 111 | 110 | 101`（这里文本从左到右是写入顺序，
不是通常的高位在左数字表示）。第三个值跨过字节边界：其第 0、1 位落在字节 0 的
第 6、7 位，第 2 位落在字节 1 的第 0 位。

| 值 | 起始 bit | 结束 bit（包含） |
| --- | ---: | ---: |
| 1 | 0 | 2 |
| 7 | 3 | 5 |
| 3 | 6 | 8 |
| 5 | 9 | 11 |

payload 为 `0xF9 0x0A`，第二字节高四位填零。demo 实际输出：

```text
width=3
raw=32 encoded=7 bytes
payload: 249 10
```

解码按同一 bit 游标逐位取出，再左移回值中的 b 位。关键不变量：处理第 i 个值前
游标为 i*w；移位量 b 严格小于 64，因此 w=64 时也不会执行未定义的 `1 << 64`。

## 源码导读与成本

- `src/codec.h` 提供 bit_width、required_width 和两种 encode 接口。
- `src/codec.cpp` 从位宽计算、逐位写入到逐位还原完整实现算法。
- `src/demo.cpp` 展示真实负载字节与总编码长度。
- `tests/codec_test.cpp` 包含手算字节 oracle 和固定种子 19445 的全位宽随机往返。

位宽扫描最多 O(64n)，编解码 O(n*w)，w≤64；输出为 5+ceil(n*w/8) 字节，
解码输出 O(n)，工作空间 O(1)（不含输入输出）。n 的资源上限保证 n*w 不溢出 size_t。
这不是 SIMD 优化版：为了清晰逐位处理，吞吐量低于机器字批量打包。
一个离群大值会令整块 w=64，结果比原始数据多 5 字节；实际系统可分小块或用例外值编码。
本教程不实现这些额外策略，不承诺任意分布都压缩。

## 验证边界

测试 w=0、w=64、空输入、单项、重复零与重复 UINT64_MAX；对 0..64 每一种宽度执行
十组随机往返并通过掩码生成合法输入。手算负载验证比“两个错误互相抵消”的往返更强。
非法编码测试包括每个截断点、width=65、非零尾部填充、过大行数、额外字节；
编码端测试 3 位不能容纳 8、零位不能容纳 1、超出最大块行数。

## 构建与验证

无第三方依赖；需要 CMake 3.16+ 和支持 C++17 的编译器。独立检出本分支即可运行，
不需要检出相关主题。返回总目录使用 `git show main:README.md`，无需合并实现。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/demo
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release -j2
ctest --test-dir build-release --output-on-failure
./build-release/demo
```

本次验证环境为 macOS AppleClang 17。该主机 CommandLineTools 默认未找到 SDK 中的
libc++ 头文件，配置时实际额外传入下面参数（正常工具链不需要）：

```sh
-DCMAKE_CXX_FLAGS="-isystem $(xcrun --show-sdk-path)/usr/include/c++/v1"
```

测试程序与 demo 分离；`tests/check.h` 失败时抛异常，使 CTest 返回失败，
不使用会在 Release 中消失的 `assert`。构建启用标准 C++17、关闭语言扩展、开启警告。
`src/bytes.h` 是本分支自带的小端读写支撑，不依赖其他 checkout；越界读取、
非法数量、残余字节等格式错误抛 `std::invalid_argument`，内存分配失败由标准库报告。

## 共通边界

这是内存块编码实验，不是数据库文件格式：没有版本号、校验和、页 I/O、并行压缩或
自动选择最优编码器。每块最多 1,000,000 个元素；这是明确的资源约束，不是类型本身的上限。
不能检测“损坏后恰好仍合法”的字节流，也不声称压缩总是节省空间。
大小比较使用真正生成的 `Bytes::size()`，包含本格式元数据，不是 C++ 容器 `sizeof`；
不计分配器容量、对象头、临时工作空间。教学时间成本是 RAM 模型分析，不是磁盘实测。
